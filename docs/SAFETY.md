# Safety model

A cleaner is only useful if you can trust it. This page states exactly what `cna` will and will not do.

## What happens to what

| Item | Action | Recoverable? |
|---|---|---|
| Cache / temp files from the built-in rules | **Deleted** (`clean --yes`) | No - but they are regenerated by the applications that own them |
| Duplicate files | **Moved to quarantine** (`dupes --quarantine --yes`); the keeper is never touched | Yes, `quarantine restore ID` |
| Leftover folders of removed apps | **Moved to quarantine** (`remnants --quarantine --yes`) | Yes |
| Quarantined items | Deleted permanently only by `quarantine purge --yes` or by `auto run` after `quarantine_keep_days` (default 30) | No |
| Registry keys / values (leftover search) | **Never modified** - only read and reported | n/a |
| Folders suggested by `recommend` | **Moved to quarantine** (`recommend --apply --yes`), never deleted outright | Yes |
| Debloat: privacy values, startup items, services, hibernation | **Changed** by `debloat apply --yes`; previous values journaled | Yes, `debloat undo` |
| Debloat: Store apps | **Removed** only with `--apps` / the tray command | **No** (reinstall from the Microsoft Store) |
| Your documents, browser bookmarks/passwords/history, saved games | Not covered by any rule | n/a |

## Preview first, everywhere

* `scan` never changes anything. `clean`, `dupes --quarantine`, `remnants --quarantine`, `quarantine purge` do nothing
  unless `--yes` is passed.
* The widget adds a second step: the action button turns into **Confirm** and must be clicked again within 5 seconds.
* The preview and the real run use the same traversal, so what you saw is what runs.

## Protected locations

`cna` refuses to use as a cleaning target, or to move into quarantine, any path that is:

* a drive root or only one folder deep (`C:\`, `C:\Users`);
* exactly one of: the user profile, `AppData`, `AppData\Local`, `AppData\Roaming`, `Program Files`,
  `Program Files (x86)`, `ProgramData`, the Windows folder, the system drive root, or the user's
  `Desktop`, `Documents`, `Downloads`, `Pictures`, `Videos`, `Music`, `OneDrive`;
* **an ancestor of any of those** (so a rule pointing at a folder that *contains* your Documents is refused too).

This applies to built-in rules, `custom_rule` entries and every quarantine move. A refused rule prints
`refused (protected location): <path>`, and it cannot hide other legitimate rules.

## Things `cna` never does

* follow or delete symbolic links and junctions;
* read cloud-only (OneDrive/placeholder) files - that could trigger downloads;
* treat hard links as duplicates, or count them as reclaimable space;
* write to the registry, stop services, or kill processes (files in use are simply skipped);
* elevate itself - rules needing administrator rights are skipped and listed;
* touch paths you pass with `--exclude` / `exclude =`;
* send any data off the machine (there is no networking code).

## Known side effects of cache cleaning

| Cleaned | What you notice afterwards |
|---|---|
| Browser caches | Pages load slower once while the cache refills. Sign-ins, bookmarks and history are *not* cache and are untouched. |
| Shader caches (`gaming`) | Games stutter briefly on first launch while shaders recompile. |
| `gradle-cache`, `cargo-registry`, `npm`/`pip`/`yarn` caches | The next build re-downloads dependencies. |
| Thumbnails | Explorer rebuilds thumbnails when you open a folder. |
| Windows Update download folder (`windows` profile) | Nothing; installed update payloads are re-downloaded only if needed. |

## Judging leftover candidates

The score is a confidence, not a verdict. Before moving anything:

1. Read the `reason` line (e.g. "no installed app matches ...; untouched 412 days").
2. Run `cna explain <path>` - it shows the folder's contents, size and likely owner.
3. Treat `unregistered-program` (executables in Program Files, no uninstall entry) with extra care: it may be a
   portable program you still use.
4. Start with `--min-score 80`; lower it only after you are comfortable with the results.

Matching is intentionally generous towards "still owned", so real leftovers can be missed; that is the safer failure.

## The model and the advisor

* The model **proposes**; it never deletes. Anything `recommend` applies goes to quarantine and can be restored.
* A non-learned gate overrides it: sensitive names (credentials, keys, wallets, saves, `tdata`, `Package Cache`, ...) are never `clean`; `clean` requires a cache-like name or
  your earlier decision; a confident `keep` is final; your decision about an exact folder beats everything.
* Rules that know a folder are authoritative; the model can only downgrade a rule's `clean` to `review`.
* Restoring a folder teaches the model to be more careful with folders like it. Wrong suggestions are cheap to undo; wrong deletions would not be, which is why the model never deletes.
* The model reads names, sizes and dates only, never file contents, and nothing leaves your PC.
* Measured limits and caveats are in [MODEL.md](MODEL.md) section 6; the advisor has not been evaluated on real machines yet.

## Debloat

* Preview by default (`scan`; `apply` without `--yes`). Only items named in the source catalogues can be changed; unknown startup entries are left alone and
  security software / hardware drivers are never offered.
* Every registry, startup, service and hibernation change records the previous value; `cna debloat undo --all --yes` restores it exactly.
* **Store app removal is the exception**: it cannot be undone by this tool and is never part of a default run. Package names are validated before reaching PowerShell; only allow-listed apps are removable (never the Store, Calculator, Photos, Terminal, Security, Edge or runtimes).
* Items that need administrator rights are skipped (not forced) when you are not elevated.
* Windows updates, enterprise policy or security software can revert or block these settings.

## Recovery

    cna quarantine list
    cna quarantine restore <id>        # puts the item back at its original path; refuses to overwrite
    cna quarantine purge --older-than 30 --yes

Quarantine lives in the state directory (`cna config path` shows it). If the original drive differs from the state
drive, the move is a copy followed by a delete; if the delete fails, the copy is discarded and the original remains.

## Recommended rollout for automation

1. Run `cna auto run --dry-run --force` and read the summary.
2. Enable only `clean` with `quick,browser` for a week.
3. Set `remnants = report`, review what it finds in `cna.log` and with `cna remnants`.
4. Move to `remnants = quarantine` with a high `remnants_min_score` and a generous `quarantine_keep_days`.
5. Use `dupes = quarantine` last, with a large `dupes_min_size` and explicit `dupes_roots`.

## Limits of this guarantee

The protections above are covered by automated tests on Linux (see `TESTING.md`), but the Windows-specific code
(junction detection, cloud-placeholder detection, registry reads, elevation checks) has not yet been verified on real
Windows. Until you have run the checklist in `TESTING.md`, keep `--exclude` entries for anything precious and prefer
previews.
